Brancher un vrai front

1. Servi par l'API : construire le front avec son outil, puis lancer : 

paragone --serve --public ./dist

Le dossier est servi à /. Une page sans extension qui n'existe pas (par exemple /leads/12) renvoie son index.html, pour un routeur en mode « history ». Les chemins /api et /openapi sont réservés. Le front appelle l'API en chemins relatifs : fetch("/api/leads").

2. Hébergé ailleurs : lancer l'API en autorisant son origine : 

paragone --serve --cors http://localhost:5173

Le front appelle alors l'URL complète : fetch("http://127.0.0.1:7331/api/leads"). Sans --cors, un autre site ne peut pas lire l'API. Un serveur de développement qui fait proxy de /api vers l'API n'a pas besoin de --cors : le navigateur ne voit qu'une seule origine.

Le contrat /openapi/json décrit chaque route, ses paramètres et ses réponses : un générateur de client (par exemple openapi-typescript) peut en tirer des types.
